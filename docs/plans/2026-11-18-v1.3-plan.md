## 目标

两项：① **会话活动提取**——多会话面板每行显示该会话「正在做什么」（transcript 尾部 tool_use 提取）；② **顶部拖拽修复**——自绘拖拽越过 AppKit 顶边约束，猫可贴到菜单栏下缘。

## 背景调查（设计依据，均已实证）

- **todos 数据源不存在**：`~/.claude/todos/` 目录缺失、全盘无 todo JSON、二进制内仅权限白名单字符串、唯一「用过 TodoWrite」的会话实为 thinking 文本——原设想的「3/7 进度」不可行，缩水为 transcript 活动提取。
- **活动提取活体验证**：本会话 transcript 尾部 `type=assistant` 行的 `content[]` 内 `type=tool_use` 块可精确还原当前动作（`Bash: python3 …`）。watcher 本就尾读同一文件，纯增量。
- **拖拽卡顶根因**：macOS 原生窗口拖拽（NSWindow 内建，tauri `startDragging` 直通）约束「窗口顶边不得越出屏幕顶」，底/左右可部分越出。pet 窗固定 288×312、猫在底部 → 顶边被挡时猫头距屏幕顶 ~104px（zoom 1.0），zoom 越小观感越差。程序化 `setPosition` 不受此约束。

## Task 1: 会话活动提取（watcher 侧）

**Files**: Modify `src-tauri/src/watcher.rs`（含 `#[cfg(test)]`）
**Interfaces**:
- 纯函数 `fn extract_activity(row: &serde_json::Value) -> Option<String>`
  - 条件：`row["type"] == "assistant"` 且 `row["isSidechain"] != true`；取 `message.content[]` 中首个 `type == "tool_use"` 的块
  - brief 取 `input` 中第一个存在且非空的字段，优先级 `command > file_path > description > pattern > url > query`；全无 → 只用工具名
  - 输出 `"Name: brief"`（brief 单行化：连续空白折叠为一个空格）；超 60 字符截断加 `…`；无 tool_use → `None`
- 集成：尾读新行时更新 per-session `last_activity`（有新 tool_use 才更新；**idle 后保留最后值**不清空）；snapshot 组装时写入 sessions[] 元素新字段 `activity`（无值 → `null`）

**行为**:
- 首见 offset=EOF 的既有语义不变 → **应用启动时已在跑的会话，要等它下一个回合写行后才有活动**（验收预期，README 注明）
**测试**（cargo，fixture 行直构）:
- Bash(command)→`Bash: npm test`；Edit(file_path)；Read(file_path)；Grep(pattern)
- 超长 command 截断 60+`…`；含换行/多空白折叠单行
- `isSidechain=true` 行 → None；`type=user`/system 行 → None；content 无 tool_use → None
- input 无优先级字段 → 仅工具名；多 content 块取首个 tool_use
**验收**: 开两个会话各跑不同任务 → 面板对应行下灰色小字实时（≤2s）显示「工具: 参数」；任务结束空闲后保留最后活动

## Task 2: 自绘拖拽（顶部可贴）

**Files**: Create `src/drag.ts` + `src/drag.test.ts`；Modify `src/main.ts`（pointer 状态机）、`src-tauri/capabilities/default.json`（按需补 `core:window:allow-set-position`、`core:window:allow-current-monitor`）
**Interfaces**:
- `src/drag.ts`:
  - `export function grabOffset(cursor: Physical, origin: Physical): Physical`（mousedown 时一次性：光标 − 窗口原点，物理坐标）
  - `export function clampDrag(pos: Physical, winW: number, winH: number, bounds: MonitorBounds, margin = 48): Physical`——窗口矩形与显示器**可见区**（visibleFrame，菜单栏下缘为顶）交集在两轴均 ≥ margin，越界钳到边界；显示器内本来就不越界 → 原样返回
**行为**:
- pointer 状态机：`dist > 4` 时不再调 `startDragging`，置 `dragging = true` 进入自绘；mousemove 经 rAF 合并节流：`cursorPosition()` → `pos = cursor + grabOffset` → `clampDrag`（显示器 bounds 用 mousedown 时的 `currentMonitor()` 缓存，拖拽中每 ~500ms 刷新一次以覆盖跨屏拖动）→ `getCurrentWindow().setPosition(PhysicalPosition)`
- mouseup / 失焦结束拖拽；click 判定（dist ≤4 且 <400ms）与 hit-test 手势钉（pointerPressed/dragging 禁翻穿透）**零改动**
- 快速拖动丢帧可接受（rAF 档），但不丢窗口
**测试**（vitest，`src/drag.test.ts`）:
- `grabOffset`：差值正确、物理坐标直传不改值
- `clampDrag`：屏内原样；顶部越界钳到 visibleFrame 顶；左/右/底各钳到 48px 可见；窗口比显示器大时钳到 margin 兜底不出现负宽负高
**验收**: 猫可拖到**贴住菜单栏下缘**；快速甩动不丢窗口；点击/双击/右键/穿透行为全部照旧；猫永远留屏内 ≥48px
