## Task 1: 链接系统浏览器打开（最小，先做）

**Files**: Create `src-tauri/src/opener.rs`；Modify `src-tauri/src/lib.rs`（mod+注册）、`src/chat.ts`（点击委托）、`src-tauri/capabilities`（如需）
**Interfaces**: `#[tauri::command(async)] pub fn open_external(url: String) -> Result<(), String>`
**行为**:
- 校验：url 必须以 `http://` 或 `https://` 开头，否则 Err 拒绝（防任意协议/命令滥用）
- macOS `Command::new("open").arg(url)`（不经过 shell，单参数无注入面）；非 macOS → Err("unsupported platform")
- chat.ts：消息区事件委托——click 事件找 `closest("a")`，有 href 则 preventDefault + invoke("open_external",{url})，失败 toast
**测试**: Rust 单测——http/https 放行、ftp/file/javascript:/空串拒绝（Command 构建断言）
**验收**: 让 Lynn 回复一个含链接的 markdown → 点击 → 默认浏览器打开；气泡窗不导航

## Task 2: 精灵动画 CPU 优化

**验收**: 活动监视器对比优化前后空闲 CPU（应用进程预期 3.0% → ~1.5%，给出测量命令）

## Task 4: 多会话视图

**Files**: Modify `src-tauri/src/watcher.rs`（tick 末 emit snapshot）、`src/main.ts`（监听+右键菜单）、Create `sessions.html` + `src/sessions.ts` + `src/sessions.css`；Modify `src-tauri/capabilities`（新窗口权限）
**Interfaces**:
- 新事件 `sessions-snapshot`：每 poll tick 发 `{sessions: [{sessionId, cwd, name, status, updatedAtMs}]}`（watcher 已有 alive 列表，含 pet 自身会话，标注不加区分）
**行为**:
- watcher：tick 末尾对 alive 列表整体 emit（payload 小，2s 一次可接受）
- main.ts：listen 存最新快照；**右键猫**（contextmenu 事件）→ toggle sessions 窗口（label "sessions"，320×380，hide/show 生命周期照抄 chat 模式；无 light-dismiss，×/Esc 关）
- sessions.ts：listen snapshot → 渲染列表行：项目名（cwd basename，format.ts projectOf）+ 会话名（name）+ 状态点（busy=绿呼吸动画 / idle=灰）+ 相对时间（「活跃 3s 前」，interval 更新）；空列表显示「没有运行中的会话」
- 窗口无输入框，纯展示；capabilities 沿用 chat 条目模式加 "sessions"
**测试**: watcher 侧 snapshot payload 单测（复用 golden fixture）；前端渲染人工验收
**验收**: 开着多个 Claude Code 窗口 → 右键猫 → 面板列出全部（项目/状态/活跃时间）；某窗口跑任务 → 状态点实时变绿

## Task 5: 立绘多皮肤

**Files**: Modify `assets/pet/pet.json`（skins 映射）、`scripts/import_generated_sheet.py`（--skin 参数）、`src/main.ts`（皮肤加载/切换）、`chat.html/chat.ts`（⚙ 面板皮肤芯片）、`src-tauri/src/settings.rs`（petSkin 字段）、`src-tauri/src/settings.rs` 测试
**Interfaces**:
- pet.json：`"skins": {"default": {"spritesheetPath": "spritesheet.png", "displayName": "像素猫"}, "<id>": {"spritesheetPath": "skins/<id>/spritesheet.png", "displayName": "…"}}`（无 skins 字段 = 单皮肤向后兼容）
- settings.json 增 `petSkin`（默认 "default"；load 时校验在 skins 集内否则回 default）
**行为**:
- import 脚本：`--skin <id>` → 写 `assets/pet/skins/<id>/spritesheet.png` 并把该皮肤注册进 pet.json skins；无参数 → 现行为不变（覆盖默认皮肤）
- main.ts：loadPet 按 settings.petSkin 解析对应 spritesheetPath（ skins 缺失回 default）；加载后重建精灵动画
- ⚙ 面板：皮肤芯片组（每皮肤一枚，displayName），点选 → save_settings + 通知 pet 窗换肤（新事件 `skin-changed` {skinId}，pet→pet 自事件或 settings 面板直接 emit 全局——取实现最简者并在报告注明）
- 换肤即时生效，无需重启
**测试**: settings petSkin 归一化测试（非法/缺皮肤回 default——需 load 时不知道可用集，回 default 即可）；import 脚本 --skin 冒烟（跑脚本验证生成路径，不进 cargo test）
**验收**: 用官方 prompt 生成新网格图 → `--skin official` 导入 → ⚙ 切换两套皮肤即时生效、重启保持
