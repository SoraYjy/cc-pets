# cc-pets v1.3.x 拆分方案:原生菜单 + 设置窗口

> 状态:待 Sora 确认后开工(superpowers 流程:本方案 → 逐任务子代理实现+评审 → 人工验收)
> 基线:HEAD=339524c(cc-pets 改名 + v1.3 收官),main,远端已关联

## 目标

应用化收尾:设置从气泡 ⚙ 面板迁入**原生 macOS 菜单栏**(app 名 → 设置…,⌘,),打开独立设置窗口;气泡 ⚙ 瘦身为会话快捷操作(只留清屏/重开)。应用图标另批处理(Sora 之后提供源图,本批不做)。

## 现状与设计

- 设置四项:style(气泡风格 a/b/c)、opacity(气泡透明度)、petSkin(皮肤)、pet_zoom(猫大小)。存 `~/.cc-pets/settings.json`,命令 `get_settings`/`save_settings` 已有,零改动。
- 现状链路:气泡 ⚙ 面板读/存设置;换肤发 `skin-changed`、缩放发 `pet-zoom-changed`(pet 窗监听);风格/透明度在 chat 窗本地应用。
- 新链路:原生菜单「设置…」→ Rust 打开/聚焦独立 `settings` 窗口 → 设置窗口读/存(同一对命令)→ 通知生效:发既有 `skin-changed`/`pet-zoom-changed`(pet 零改动),发**新事件 `chat-appearance-changed` {style, opacity}**(chat 窗应用外观)。
- 气泡 ⚙ 瘦身:移除四项设置 UI 与其读写逻辑,保留「清屏」「重开会话」两按钮(chat-clear-history/chat_restart 链路零改动)。

## 全局约束

- Mac only;既有事件契约除**新增** `chat-appearance-changed` 外零改动(skin-changed/pet-zoom-changed 保留,改由 settings 窗口发)
- 允许新增文件:src/settings.html、src/settings.ts、src/settings.css;允许修改:src-tauri/src/lib.rs(菜单+窗口)、src-tauri/capabilities/default.json、src/chat.html、src/chat.ts、src/chat.css、src-tauri/tauri.conf.json(settings 窗口声明如采用配置式)、README.md
- capabilities:`windows` 数组加 `"settings"`(窗口需要 invoke 命令与事件)
- 回归网:vitest 现有 89 枚不得回归;新增逻辑若可抽纯函数(如菜单 accelerator 常量、窗口 label)加测试,否则评审覆盖;`npm run test:all` 为门
- 每任务独立提交 + 评审;message 末尾 Co-Authored-By

## Task 1: 原生菜单 + 设置窗口壳(Rust + 骨架)

**Files**: Modify `src-tauri/src/lib.rs`、`src-tauri/capabilities/default.json`;Create `src/settings.html`、`src/settings.ts`(骨架)、`src/settings.css`(空样式挂接)
**Interfaces**:
- Rust setup 里构建应用级菜单(菜单仅在应用任一窗口激活时可见,macOS 常规行为):
  - App 子菜单:「设置… cc-pets」(加速键 CmdOrCtrl+,)→ on_menu_event 打开设置窗口;分隔线;「隐藏 cc-pets」(Hide role);「退出 cc-pets」(Quit role)
  - Edit 子菜单:标准 role(Copy/Paste/SelectAll,输入框通用)
  - Window 子菜单:Minimize/Zoom role
- 设置窗口:label `"settings"`,约 360×420,decorations true(原生标题栏),resizable false,标题「cc-pets 设置」;open 语义 = 已存在则 show+focus,不存在则 create(创建走 Rust WebviewWindowBuilder,visible true)
- settings.html/ts 骨架:载入后 `get_settings` 并把四项值渲染到 DOM(占位 UI,T2 填交互);暴露全局函数供 T2 接线
**行为**:
- 菜单事件在 Rust on_menu_event 处理;「设置…」打开窗口逻辑放 Rust(避免跨窗口事件时序问题)
- settings 窗口所有权:close = hide(与 chat/sessions 同生命周期策略)——关闭按钮点下后 hide 而非销毁,状态保留
**测试**:cargo check + 人工验证菜单出现/点击打开窗口;窗口 hide/show 循环
**验收**:打包版菜单栏出现 cc-pets → 设置…(⌘,)能打开设置窗口;窗口可关可重开

## Task 2: 设置 UI 迁移 + 事件接线 + 气泡瘦身

**Files**: Modify `src/settings.ts`、`src/settings.html`、`src/settings.css`(完整 UI)、`src/chat.ts`、`src/chat.html`、`src/chat.css`(瘦身)
**Interfaces**:
- Consumes:Task 1 窗口;`get_settings`/`save_settings`;`skin-changed`/`pet-zoom-changed` 事件(pet 侧已有监听,零改动)
- Produces:新事件 `chat-appearance-changed` {style: "a"|"b"|"c", opacity: number}(settings 窗口发,chat 窗监听应用)
**行为**:
- settings.ts:四项控件完整迁移自 chat ⚙(风格芯片 a/b/c、透明度滑杆 0.3-1.0、大小滑杆 0.5-1.5、皮肤芯片 displayName 列表——皮肤列表当前硬编码两枚,照搬现状不新增动态拉取);改动即 save_settings + 发对应事件(skin→skin-changed,zoom→pet-zoom-changed,style/opacity→chat-appearance-changed);打开时 get_settings 回填
- chat.ts:监听 chat-appearance-changed → 应用 style 类与 --win-alpha(复用现有 apply 函数);⚙ 面板删除四项设置 UI 与其读写/发事件代码,保留清屏/重开;chat.html 同步删 DOM;chat.css 删除死样式
**测试**:vitest——theme.ts 纯函数已有测试保持;新增可抽纯函数(若有)加钉;人工验收:四项设置在设置窗口改 → 气泡外观/猫皮肤/猫大小即时生效且重启保持;气泡 ⚙ 只剩两按钮且功能正常
**验收**:全链路手动清单——设置窗口改四项各自即时生效;重启 app 设置保持;气泡清屏/重开正常;气泡旧 ⚙ 设置 UI 不复存在
